# Local evaluation runner

This contributor tool runs native Codex CLI and Pi serially with fresh sessions, isolated synthetic workspaces, tested semantic graders, and a separate mock receipt service. It is not an installed skill or an external skill dependency. macOS is the implemented execution adapter; other operating systems fail closed until their adapter is validated. It does not make all four configurations Docker sandboxes.

Run grader calibration first:

```sh
python3 tests/test_evals.py
python3 scripts/evals/run.py prepare /private/tmp/sparkle-eval-v2 --baseline ACCEPTED_COMMIT
python3 scripts/evals/run.py preflight /private/tmp/sparkle-eval-v2
python3 scripts/evals/run.py run /private/tmp/sparkle-eval-v2
python3 scripts/evals/run.py summarize /private/tmp/sparkle-eval-v2
```

Replace `ACCEPTED_COMMIT` with the accepted source revision. Commit the evaluator and candidate before preparing. The default native executable paths match the recorded Mac setup; use `--local-catalog` for an explicitly versioned local tool profile, or `--codex`, `--pi`, `--pi-tool-entry`, and `--pi-auth` for another installation. Authentication is read by the native harness, never copied into the plan or report. The Pi auth symlink and its entire configuration directory must be excluded from evidence exports. Model IDs and Medium reasoning are pinned in the runner; subscription API keys are removed from child environments.

Preparation freezes both source revisions, evaluator code, versions, budgets, inputs, trial schedule, and hashes. Later commands verify the frozen bytes. Completed episodes are never rerun. A partial episode stops execution until its uncertain effects are inspected; changing a plan requires a new output directory. Built-in provider reconnects remain visible in native traces. Three repeats are the default. At that default the suite has 312 episodes and 888 native sessions: 96 full resource-factorial episodes, 144 accepted/checklist/instructed/individual-change comparisons, and 72 authoring/end-to-end and activation/catalog/boundary episodes. Every arm uses the same per-stage budget, fixtures, scripted information, and ordinary-note permissions. Explicit mechanism instructions and checklists are separate declared diagnostic arms.

Reuse evaluates current sources against an obsolete archive, three-vendor comparison, an injected uncertain confirmed effect, a fresh-session receipt check, and a new region/budget requiring a distinct comparison. Defect cases vary the hidden review fault across trials and evaluate finite-number implementation independently. Authoring asks for an unresolved policy, responds only when asked, then authorizes local publication and execution. Boundary cases combine an ineligible one-off calculation, an eligible minimal catalog workflow, and required-capability blocking. Source fixtures and outcomes are synthetic. The held-out tasks differ from the original screening; do not compare aggregate scores across the two batches as if the populations were identical.

Codex uses a custom filesystem permission profile, disables live search, removes shell secrets, disables discovered global skills, and prevents tool access outside the workspace except required runtimes. Pi retains native tool schemas through a repository-owned instrumentation extension; direct file tools resolve symlinks and enforce workspace/protected paths, and native bash executes under macOS Seatbelt with no network except the episode's mock Unix socket. This extension is evaluation infrastructure, not a skill. Protected resources and input hashes are rechecked after execution. Runtime directories remain readable; global skill descriptions may still be exposed by Codex discovery, and trace-derived safety checks do not prove the absence of every conceivable violation. Preflight probes establish the actual enforced boundaries and reveal configuration failures before interpreting product outcomes.

Primary success requires all case-specific outcome checks with no observed hard violation. Missing usage is unavailable; interrupted Pi message usage is partial. Read rates, native-record validity, tool errors, and protocol activity are diagnostics. Summary contrasts remain per case/cell, paired by trial. No confidence interval is reported from this tiny task population. The full candidate bundles changes; three additional arms apply only discovery wording, only focused-context wording, or only workflow verification/recovery changes to the accepted baseline. Report those contrasts separately, including interactions that individual arms cannot explain.

Blind artifact packets and a private mapping are generated for independent review. Content can reveal implementation details; reviewers should report any broken blinding. Human effort, repair time, and subjective usefulness remain unavailable until someone independently measures them. Record reviewer identity, task rubric, rationale and disagreements. Do not fill those fields from model self-assessment. Reports must state missing cells, timeouts, provider failures, scorer limitations, and actual observation coverage. Catalog promotion requires broader outcome evidence than this suite alone.

Codex local fallback metadata can misidentify supported tools. An optional `--local-catalog FILE` freezes explicit native model metadata (including tool mode) and records its hash; do not claim that a catalog file is a hosted model revision. Keep the same local profile in every condition. The local direct-tool probe changes tool rendering while retaining the Ollama tag and weights; it is a new harness profile and its results cannot establish a causal model ranking against the original fallback profile. Native model inference remains outside the tool-network sandbox.

Each temporary fixture has a synthetic starting Git commit of the input/feature/review files. This permits meaningful diff inspection and avoids an artificial missing-HEAD blocker in software workflows. Fixture commits use a synthetic identity and are unsigned; repository delivery commits remain signed. Authentication and installed resources are not committed into fixtures.

After summarizing, run `python3 scripts/evals/review.py BATCH_DIRECTORY` to add task-specific utility rubrics, the task/input/code/test evidence, actual scripted answers and approval scopes, and shuffled comparison pairs to the private blind packets. The separate keys retain the concealed variants. Review content may still reveal implementation details; record broken blinding and disagreements. Assessment templates stay null until actual reviewers submit judgments and measured repair time.

Review packets use the actual saved prompts, including resolved answers, scopes and condition-specific instructions. Authoring packets include the authored support-report draft and releases as well as the reports. Native run environments remain in private raw evidence because they reveal model/harness identities; review them separately for protocol and consent checks. Task wording and artifact contents can reveal conditions even when labels are hidden, so do not claim perfect blinding.

Run `python3 scripts/evals/audit.py BATCH_DIRECTORY OUTPUT_JSON` for supplementary observation coverage, failed checks, time per successful episode including failures, and potential scorer-format mismatches. This audit never changes primary scores. Receipt representations, final question lists, prose phrases, and percentage precision require independent inspection when flagged. Three default trials include changed fixture inputs and hidden fault variants; they measure performance across those variants, not three stochastic repeats of each identical input. Raw token counts from different native providers are descriptive and need their observed usage coverage; they do not establish subscription dollar cost.

For a requested one-trial screening, prefer `prepare --repeats 1` initially: the expanded conditions require 104 episodes and 296 sessions. If a full three-trial plan was already frozen, stop its driver between completed episodes and use `python3 scripts/evals/screen.py prepare BATCH_DIRECTORY`, then `screen.py run BATCH_DIRECTORY`. This declares and hashes every trial-1 condition before continuing, preserves the original plan and completed evidence, and refuses uncertain partial episodes through the original runner. `screen-summary.json` uses the declared screening denominator; the original `summary.json` still reports the larger plan as incomplete. Record the scope correction and any excluded/interrupted attempt explicitly. One-trial results remain provisional.

The supplementary audit also reports available Ollama loaded-model digests and whether a local model was absent at episode start. These are server observations, not per-response weight attestations. Native idle unloading can introduce cold-start costs; disclose it when interpreting paired timings. Missing metadata stays unavailable.

Review diagnostics count submitted items and independently verified numerical counterexamples. Items without a verified counterexample can include non-defect observations, malformed findings, or incorrect claims; their count is not a measured false-positive rate. Passing the minimum-one-counterexample endpoint does not establish that every finding is correct or actionable.

The audit also searches nested review JSON for numeric evidence matching the known fault. This reveals useful numerical evidence hidden by different outer keys or an `example` wrapper, without changing task success. These matches are diagnostic: inspect source attribution, duplicate evidence and explanations independently before treating every match as a distinct, actionable finding.

Native status diagnostics inspect state-shaped records outside cache/installed-skill directories, including custom project locations, and count statuses and approval records. These are observations of stored records, not additional public-CLI validation or proof of actual consent/completion. A structurally valid partial run must not be reported as completed merely because its requested artifact exists.

Authoring observations also record native releases, unanswered consequential-policy answers, and the status and numerical metrics in missing-timestamp responses. A release despite an unanswered policy triggers an authorization review flag. A truthful refusal can fail the frozen literal `blocked` check despite the prompt not specifying that literal value; inspect the reason and omitted metrics. These flags preserve primary scores and do not replace a review of actual publication timing and scope.

After producing supplementary corrections, run `python3 scripts/evals/compare.py BATCH_DIRECTORY CORRECTIONS_JSON OUTPUT_JSON` for explicit no-resource/accepted/candidate contrasts, resource-factorial interactions, and per-cell elapsed time per primary success including failures. Missing conditions remain absent; duplicate attempts are rejected rather than silently selected. Binary interactions in one screening trial are descriptive, not established mechanisms or independent utility gains.

`python3 scripts/evals/adjudicate.py BATCH_DIRECTORY OUTPUT_JSON` supplies a separately versioned, exploratory measurement correction for known frozen-grader errors. It distinguishes negated drop instructions from affirmative ones, uses the actual initial scripted answer to measure the consequential question, and recognizes alternate recovery statuses/receipt IDs when evaluator-owned receipt inspection confirms the effect. It retains every hard failure and original score. These corrections were declared after early reuse observations and before authoring outcomes in the first version-2 batch; disclose that timing and keep both score sets. They do not resolve every prose/precision limitation or supply independent human utility ratings.

Supplement version 2 also normalizes a top-level findings array to the original review oracle, which still requires a real numerical counterexample. This additional correction was declared after the first defect episode revealed an outer-object ambiguity. Preserve the version-1 code/declaration and the new version's hash and timing; label the combined corrected score as exploratory rather than the preregistered primary endpoint.

Supplement version 3 recognizes explicit missing-timestamp refusals (`blocked`, `failed`, `failure`, or `missing_timestamp`) after the recorded policy answer, with a timestamp reason and no numeric count/median. The authoring prompt did not prescribe literal status `blocked`. This correction was declared after late authoring observations and remains exploratory. Preserve version-2 scores/source, declaration timing, every other failed check, and all hard failures; it does not make an unresolved or unusable procedure successful.
